# Experiment 3 结果解释：支持什么，还缺什么

初步判断：本组结果支持“所采样连续驾驶片段中的离散语义依赖存在时序冗余，原始 Senna 仍对每条请求执行完整 Prefill/Decode”的动机。尚不足以证明可部署系统能够安全跳过相同比例的推理，也不足以证明 WorldStream/QCSE 的实际加速。以下是基于原始文件的描述性分析，不是正式独立科研审定。

## 数据与原始统计

3 个官方 val 场景、每场景前 20 个选定关键帧，约各 10 秒。54 条序列和 436 次真实查询来自这些片段的不同前缀与负载，不能作为 54 个独立场景；228 个不同 sample/模板，60 个 sample。相邻同模板统计已去重，共 212 对。

下表的百分比和时延均为场景等权均值；计数是实际 pair 数。Oracle 比例在当前定义下恰好等于依赖稳定率，不能当成独立的第三份证据。

## 支持的结论

1. **固定事实查询有较高的离散依赖稳定性。** 单独统计 Category/Existence/Position，127 个 pair 中有 102 个满足当前 Oracle 条件，即 pooled 80.31%。若合并全部类型，为 163/212=76.89%；合并值包含使用离线预测/规划标签的乐观 Oracle，不能直接解释成可观测当前世界事实的复用率。
2. **相同答案不能保证依赖不变。** 全部 pair 中有 28 对答案相同但依赖变化，其中事实查询 13 对、Position 10 对。Position 在 scene 等权口径下答案稳定率为 98.25%，依赖稳定率仅 72.90%，相差 25.34 个百分点。Category/Position 依赖还要求对象身份一致，因此能识别“对象换了，类别/左右标签却相同”的情形。
3. **原始模型确实每次重新付出推理成本。** 436 次正式请求全部时延分解有效，每次都有一次 Prefill。合计 E2E 869.27 秒，Prefill+Decode 688.40 秒。这里只能说明这组原始请求的实测成本，不能把其中稳定事件对应的成本直接报成系统可节省时间。

## 影响结论强度的问题

### 1. Existence 的高稳定率主要由持续负例贡献

60 个不同帧查询中 55 个 NO、5 个 YES。57 个相邻 pair 为 NO->NO 51 个、YES->YES 3 个、NO->YES 2 个、YES->NO 1 个。54 个稳定 pair 中约 94.44% 是持续 NO。这个事实仍属于语义冗余，但不能充分代表拥挤交通中目标集合的持续性或新目标发现能力。

### 2. 事实 QA 的输出协议没有对齐

Category 严格正确 0/63，Position 0/64；Category 51/63、Position 64/64 次输出达到 64 token 生成上限，Existence 也有 72/126 次达到上限。原始回答常给出整段自然语言描述，而问题和严格评分要求 nuScenes 类别名、位置枚举或 YES/NO。

因此 0% 不能直接解读成语义理解能力为零；其中包含格式、类别本体及目标指代问题。也不能把这些冗长/可能截断输出的 Decode 成本视为正常简短事实直答的通用成本。当前数据证明了“现有提示和原始 generation 设置下的实际成本”，更强的效率比较需要先建立可正确回答的同语义基线。

### 3. 运动预测覆盖很窄，简单当前速度规则就很强

不同帧的 Motion GT 只有 STOP, STRAIGHT 和 KEEP, STRAIGHT 两类，没有转弯、变道、加减速标签。使用模型同样已获得的当前 GT 速度，事后诊断规则“速度<2m/s 判 STOP，否则 KEEP，路径固定 STRAIGHT”在 57 个同口径事件上为 54/57=94.74%，scene 等权 97.14%；Senna 为 48/57=84.21%，scene 等权 91.43%。该规则不是独立调参验证后的正式基线，但足以说明当前结果不能支撑复杂未来行为预测的广泛结论。

Planning 的全局多数类 KEEP, STRAIGHT 占 100/126=79.37%，模型严格正确率为 37.30%。这不否定 GT 的时序稳定性，却说明模型回答质量和“具有实际使用价值的查询成本”还需要分开验证。

### 4. Mixed 没有展示跨类型状态复用

Mixed 的 73 次有效事件中，48 个相邻查询 pair 的 Oracle 安全机会均为 0，全部事件都被标记为历史事实不足；相邻对象依赖 Jaccard 平均为 0.1667。现实现只读取紧邻上一条请求的最小事实集合，不累积世界状态，因此没有覆盖“之前更早的查询已提供事实”的情况。这既不能支持已实现跨查询复用，也不能反证累积状态系统没有机会。

### 5. 离线 Oracle 知道当前依赖是否还成立，在线系统尚未具备这个判断

Oracle 会用当前 GT 验证历史事实有效性；预测/规划签名还包含未来衍生的 GT 标签。它是事后条件成立的机会分析，不能把“事后知道没变”直接替换成“在线无需观测就知道没变”。Planning 的导航依然是显式标记的 offline_future_route_6s 条件。

依赖签名采用离散类别/位置标签/速度区间。Position 的同目标相邻相对位移 pooled 均值约 3.17m，离散标签稳定并不表示连续空间位置完全不变。

### 6. 样本和完整序列覆盖有限

只有 3 个 scene Bootstrap 单位。Category/Position 依赖稳定率的 95% CI 为 55.56%–100%，Motion 为 44.44%–100%，Planning 为 47.37%–94.74%，不能以小数点后两位制造精确印象。

Category/Position 的每种长度只有 1 个标注完整的序列；长度 20 的 Motion 和 Mixed 没有标注完整序列，累计成本图对应部分缺数据。其余序列仍有真实有效查询成本，但不能当成完整 20 帧负载。此图适合描述原始执行成本随长度累加，不能独立验证状态复用收益。

## 目前适合写进论文的表述

> 在选取的三个 nuScenes 验证场景中，固定语义查询呈现明显的离散依赖时序稳定性。事实查询的 127 个有效相邻对中，102 对在所定义的 GT Oracle 检查下可由仍有效的历史事实支持。同时，相同答案并不保证对象身份和底层依赖保持不变。原始 Senna 对所有有效请求仍逐次执行完整语言模型推理，提示了依赖感知状态维护的潜在优化空间。

应紧接适用范围：这是小规模、离线 GT 验证的潜在机会；尚未测量实际状态维护、失效检测、事实直答成本和最终准确率/加速收益。

## 建议按优先级补充

1. 扩大独立场景覆盖，沿用预先固定的 scene 抽样规则；另设有真实 VRU 正例、对象切换、出现/消失及状态变化的分层诊断子集，分别报告自然分布和分层结果，禁止按稳定性挑选结果。
2. 先检查事实查询的对象指代、答案类别体系和格式解析；保持原始基线结果，额外建立可正确完成同一语义任务的输出协议对照。增加解码长度敏感性，并明确模型正确率与输出上限命中率。
3. 将三类事实查询与预测/规划分开叙述；增加 Motion/Planning 的状态变化与多样标签覆盖，报告同当前输入条件下的简单规则诊断基线。
4. 若论文需要跨类型机会，离线分析“紧邻上一条事实”与“截至上一帧累积的已知事实”两个明确的信息预算；只做 GT 分析，不提前实现运行时缓存。若后来需要系统收益结论，再单独评估状态更新、失效检测、正确性与端到端时延。

本次只读取已完成结果并做诊断计算，没有启动 GPU 推理、自动检测或新实验。可复核数值见 results_diagnostics.json；原始测量和统计文件保持不变。
